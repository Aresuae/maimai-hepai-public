# 外地朋友访问麦麦合拍

更新：2026-10-22。当前实现为在你电脑上运行的朋友内测入口，不需要购买服务器或修改路由器、防火墙。临时公网通道由 localhost.run 提供；电脑、网络、分享进程和隧道服务均需要保持可用。

## 启动与分享

1. 在项目目录双击 `远程分享启动.cmd`。已有 Node 及依赖即可；该文件先打包网页，再启动朋友入口与隧道。
2. 在本机网页读取门店菜单，填写昵称、预算、人数并创建共享餐桌。「邀请朋友加入这桌」卡片会同时生成专属邀请链接和二维码。点击「复制邀请链接」发给朋友，或让朋友直接扫描；也可点击「保存邀请二维码」下载 PNG 图片再发送。
3. 朋友用自己的手机或电脑打开链接、扫描二维码，无需同一个 Wi-Fi，也无需另输访问邀请码或麦当劳 Token。填写自己的昵称和预算，点击「加入这张餐桌」，即可独立选餐并保存到同一桌。二维码在浏览器本地生成，内容与复制链接完全相同；不包含发起人的麦当劳授权，也不会让朋友获得发起人身份。
4. 维持启动窗口运行。锁屏可以，睡眠、关机、断网、关闭进程都会影响访问。在启动窗口按 Ctrl+C 即可停止；由 Codex 启动时也可让 Codex 停止。

共享菜单同时展示餐品图片、名称和门店菜单展示价，缺失价格显示「待核价」，不当作 0 元。新餐桌自动带入所读取菜单的价格。旧餐桌可由发起人在下方读取同一门店菜单，再点击共享区域的「同步菜单价格」；只更新价格，不替换成员、预算或已选餐品。同桌朋友会随同步收到更新。展示价是发起人分享的菜单快照，优惠、套餐搭配后的最终金额仍以官方核价为准。

等价命令：

```powershell
# 在项目根目录执行
npm.cmd run share:build
npm.cmd run share:start
```

电脑重启后需再次启动。此版本未设置 Windows 服务、自动开机启动或禁用睡眠。请自行双击启动脚本保持运行，不能把 Codex 会话内临时启动视为系统服务。隧道断开后会自动重试，间隔从 5 秒逐步增加到最多 60 秒；持续连接至少两分钟后重置重试间隔。Ctrl+C 停止不会触发重连，程序下载、完整性校验等启动错误仍会停止并提示。

免费域名可能定期变化，重连也可能分配新域名；网页会更新链接和二维码，已经发出去的旧链接/旧图片不会自动更新，需要重新发给朋友。免费服务有速度限制，不适合作为正式比赛线上交付的稳定域名。依据：[localhost.run 免费服务说明](https://localhost.run/docs/forever-free/)。

若页面显示「等待远程分享」，启动脚本后等待自动更新，或点击「刷新邀请链接」。只运行「本机持续运行.cmd」或打开 127.0.0.1 页面，不会启动公网通道。刷新邀请不会覆盖未保存的选餐。分享进程每 15 秒更新状态，停止、重连中或超过 45 秒没有更新后，页面会收起旧链接和二维码。该状态证明本机通道进程仍运行，不保证每个地区的网络都可达。餐桌关闭或超过 24 小时后，旧邀请不能供新成员加入。

只想让朋友独立体验整个应用时，仍可使用 `data/远程访问说明.txt` 中的根网址和访问邀请码。加入既有餐桌优先使用餐桌专属邀请链接。

## 本机与访客的区别

| 入口 | 用途 | 数据和授权 |
| --- | --- | --- |
| `http://127.0.0.1:5173/` | 发起人的本机开发版本 | 原 `data/maimai.sqlite` 与本机环境授权 |
| `http://127.0.0.1:5174/` | 分享入口的本机验证 | 使用邀请码，创建独立访客工作区 |
| HTTPS 餐桌邀请链接 | 外地朋友的手机或电脑加入同一桌 | 有效餐桌邀请换取独立访客会话，再填写昵称加入 |

访客的账号、卡券与私人发布记录相互隔离；同一共享餐桌中的昵称、餐品、预算和选好状态会给同桌成员看到。公网入口绝不转发到 5173，也不读取原所有者数据库、`.env.local` 或环境里的 `MCD_MCP_TOKEN`。当前没有真正的用户注册和跨设备登录：同一浏览器 Cookie 有效期 7 天。退出访问、清除 Cookie、换设备或换用新域名后会创建新工作区，旧记录不能自动找回。关闭网页本身不会退出。邀请码有 128 个累计工作区的内测上限，不是正式用户系统。

饭局、Token 都保存在发起人电脑的 `data/share/workspaces/` 下，Token 通过每个工作区独立密钥进行 AES-256-GCM 加密。朋友连接前需要明确同意存储位置；电脑管理者可以访问磁盘，不应把此机制称为对电脑所有者保密。手机号、验证码只在麦当劳官方平台填写。访客点击“退出访问”会断开该工作区授权并撤销会话；单纯会话过期不会自动删除磁盘上的历史记录或密文。

## 当前能做什么

共享餐桌已支持真实的跨设备选餐与预算同步。发起人先读取真实菜单，在页面上方创建餐桌（2—6人），复制餐桌专属链接发给朋友即可。朋友加入后无需 Token，只能编辑自己的昵称、预算和餐品。点击保存后约 3 秒同桌可见。发起人可勾选已经标记选好的成员，点击「结算选中的人数 · 去核价」；至少 1 人即可，不必等满员或全员选好。

本次结算成员修改后，旧汇总与报价失效，需要重新汇总；未选入本次的成员可以继续选餐。商品价格、套餐默认搭配和优惠由发起人的账号最终核实；朋友的券和授权不共享。餐桌保存于 `data/shared-tables.sqlite`，有效期为创建或重新开启后的 24 小时；待结算餐品合计最多 12 份。

发起人可在共享餐桌标题下点击「取消本次合拍」，暂停邀请和选餐并保留成员、预算及餐品。每次点击「重新开启合拍」都需选择本次总名额（含发起人，2—6 人），不得少于现有成员数；想缩小人数可先从成员卡片「移出队伍」。超过有效期后也可以重新开启并续期 24 小时。重新开启后需重新汇总、核价，菜单和优惠仍以当前门店结果为准。取消合拍或移出成员不会取消已创建的官方订单。

本次所选餐品提交下单后会标记「已提交下单」，不再重复汇总，其余成员可继续选餐。付款由发起人当前连接的麦当劳账号统一完成，先核价、核对成员与餐品、确认创建订单，再打开官方支付页面；没有可用支付链接时在麦当劳 App 的订单中付款。当前账号有待处理订单时，先查询处理已有订单，再创建下一批。结果不明时停止重试，已提交的餐品不能在原桌修改；需要另点一单可新建餐桌。

已接入确认下单与官方支付交接，详见 [下单与支付](CHECKOUT.md)。跨设备投票、公开招募列表、真实消息仍未实现；原“合拍演示”的成员切换和申请回应仍为演示。

## 实现与访问保护

- `vite.share.config.ts` 生成独立客户端到 `dist/share`；原 Vinext/Worker 构建保持独立。运行原 `npm run build` 后需重新执行 `share:build`，因为其可能重建整个 dist 目录。
- `src/server/share-server.ts` 只监听 `127.0.0.1:5174`，对外只提供编译后的 HTML/静态资源白名单。没有开发服务器源码、磁盘文件、环境文件或 source map 路由。静态资源 gzip 压缩并缓存，数据请求禁止缓存。
- API 要求 JSON POST、精确 Host/Origin、有效访客会话。公网 Cookie 使用 HttpOnly、Secure、SameSite=Strict、Host 前缀，7 天有效；会话秘密只保存哈希，并与访问域名绑定。
- 邀请验证有全局速率限制；业务请求有逐会话速率限制、每工作区并发上限 2、总并发上限 12、请求体上限 96 KB。访客状态不返回其他身份或授权原文。
- 餐桌链接把随机邀请放在 URL fragment 中。网页通过同源 JSON POST 交换访客会话；服务器先检查邀请哈希、有效期、关闭及名额，不会仅凭餐桌 ID 放行。打开链接不占座；填写昵称加入时再次校验。已有会话保持原身份，其他餐桌仍需要独立邀请，不向访客提供发起人的私人数据库或 Token。
- Windows 内置 OpenSSH 建立反向连接，只转发 5174。关闭个人 SSH agent、密钥和用户配置，主机密钥记在项目私有 `data/share/known_hosts`，后续密钥变化拒绝连接。
- 服务只接受隧道注册事件中的 HTTPS 地址，不能误把服务商后台或说明页链接当作分享地址。运行状态见 `data/share/status.json`。

## 常见情况

- 5174 被占用：不要重复开多个分享进程；先停止原进程，再启动。5173 的本机开发版可同时运行。
- 页面打不开：先确认启动进程和网络正常，查看使用说明文件中的最新地址；手机可切换 Wi-Fi / 移动数据验证。免费海外通道的速度和不同地区可达性不作保证。
- 实时菜单为空或提示未连接：访客不会继承发起人的授权，需要自己的 Token。仅看演示无需 Token。
- 关闭窗口后别人打不开：符合预期。要长期使用固定链接，应再部署到持续在线服务器或配置固定域名隧道。

备用 Cloudflare 命令：`npm.cmd run share:start -- --cloudflare`。首次使用可从官方 GitHub 下载固定版本并验证 SHA-256。此次环境中该通道的 7844 连接失败，因此默认采用已验证连通的 localhost.run。不会自动修改系统网络规则。只验证本机入口可使用 `npm.cmd run share:start -- --local-only`。

备份前停止分享进程，完整备份 `data/share`（包含 SQLite、密钥、会话和邀请码）以及 `data/shared-tables.sqlite`；整个 `data` 目录均已 Git 忽略，不得发布或提交。原本机工作区的备份方法仍见 LOCAL_RUNNING.md。
