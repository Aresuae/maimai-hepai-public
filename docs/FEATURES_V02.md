# 麦麦合拍 v0.2 · 已选功能的落地规则

本轮依据你的选择，实现五项特色功能和人数选择。所有功能使用单机演示状态与虚构价格；未接入多人房间、真实 MCP 或下单。

## 1. 人数由发起人选择

- 开桌区提供 2、3、4、5、6 人按钮和昵称表单，点击“应用人数与昵称”生效。
- 昵称必填，1—12 个字符，同桌不重名。第一页不是固定四人，头像、预算、选票、确认进度、小票都跟随人数变化。
- 保留现有座位的偏好，新座位使用可编辑初始偏好。
- 应用名单会清空旧方案、投票与确认，请客设置恢复为各付各的，避免沿用旧组的付款承诺。
- 目前人数是参与演示的成员数。未来真实房间将它用作人数上限，必须等实际成员加入并提交，不能把预留座位当作已加入的人。

## 2. 我请客

- 模式二选一：“各付各的” / “我请客”。请客模式可选择本桌请客人，输入整桌预算后点击应用。
- 各付各的：每人的个人预算都是硬约束；本人餐品由本人承担，共享项目按参与者均分。
- 我请客：整桌预算是硬约束，个人预算暂不参与筛选；饮料、主餐、排除项、必选薯条和分享意愿仍有效。
- 每行同时显示“餐品金额”和“应付金额”。请客人应付整桌总额，其他人应付 0；两组金额各自加总都等于整桌总额。
- 若整桌必选餐品超预算，说明超出金额，不擅自删餐。可选薯条造成超预算的整套候选会被过滤；保留可行基础方案，不宣称穷举最优。
- 模式、请客人、预算发生变化都需要重新生成与全员确认，请客人也是确认者。
- 当前只是餐单费用安排，没有转账或真实付款。

## 3. 匿名投票

- 有两套以上方案时，发起人可以开启；只剩一套时直接确认。
- 开启投票清空旧确认。每人一票，揭晓前可改票，始终只计最后一次。
- 未投齐只显示参与人数，不显示中间票数。全员投完后锁定，展示各方案汇总。
- 得票最高的方案由发起人点击“采用”；平票时只允许从并列最高的方案里选择。采用不会自动确认。
- 投票进行中或尚未采用结果时，禁止最终确认。修改偏好、人数、付款规则或重新生成候选会作废投票。
- 单机匿名仅为交互演示：原始选票仍位于同一浏览器内存中，切换角色能看到该角色自己的票。页面明确标注这一限制。
- 真正多人版本：选票保存在服务端，成员只能读取自己的票；公共快照与 SSE 不含成员对应选项，结果只暴露计数。采用与开票必须验证 host 会话。

## 4. 随便按钮

- 文案“随便，帮我选主餐”，用户主动点击才代选，不自动代确认。
- 可勾选不吃鸡肉堡、牛肉堡或鱼排堡，至少保留一种可选主餐。排除当前主餐时自动移到第一个未排除项，并明确提示，可继续修改。
- 代选仅在菜单存在、未排除且整桌能够形成可行方案的主餐中随机；饮料、薯条要求、分享意愿和预算不变。
- 没有可行项就解释原因，不通过提高预算或取消必选项来完成随机。
- 当前排除项是口味选择，不是过敏原保证。

## 5. 默契小票

- 全员确认同一版且演示报价仍有效时自动解锁。
- 展示真实可推导的共同点，例如“2 人同选鸡肉堡”“3 人共享一份小食”，不制造默契百分比或人格判断。
- 包含人数、方案、版本、每人餐品、餐品金额、应付金额和整桌总额。
- 支持复制文本和下载 SVG 图片；昵称按文本渲染，SVG 转义。
- 清楚标记“虚构菜单与价格 · 非订单 / 非付款凭证”。撤回确认、改动方案或报价到期后不能继续生成当前小票。
- 已保存到设备的图片是历史快照，无法远程撤回；版本和演示标签保留在图中。

## 6. 固定饭搭子

- 为当前已应用的成员与偏好命名保存，最多 8 组，每组名 1—24 字符；提供载入和删除。
- 只在当前浏览器 localStorage 保存，键为 maimai-hepai:buddies:v1；刷新可重新读取。
- 存储采用字段白名单，只保存昵称、颜色和饮食偏好，不保存投票、确认、付款承诺或任何 Token。
- 载入即复制成新一桌待检查的偏好，需要重新生成、投票与确认。请客策略不随组保存。
- 数据格式不兼容或损坏时不自动覆盖旧记录；显示读取失败提示，用户仍可继续体验。显式保存或删除才写入存储。
- 这些是本地分组模板，还不是跨设备好友关系或邀请码通讯录。

付款策略变化、名单变化与偏好变化都会提升房间 revision；重新出方案与开投票提升确认版本。每轮选票附带 round，旧轮选票拒绝接收。
