## 阶段 1：真实协作（可先用演示菜单，不需要 Token）

- 本机基础已完成：个人 MCP Token 验证/加密保存/断开，SQLite 饭局持久化、旧浏览器数据迁移、事务版本冲突检查及持续运行启动脚本。仍无多用户账号、公开匹配或房间服务；详见 LOCAL_RUNNING.md。

- 同城搭子交互原型已可评审：虚构样例、匹配申请、本人本机发布与管理。发布记录已改为 SQLite 保存，可编辑、关闭及重新招募；真实公开发布仍依赖本阶段多用户账号、房间和权限。
- RoomRepository 持久化、成员会话、权限与邀请，2—6 人名额由发起人设置。
- 写入版本检查、事务、SSE、断线恢复。
- 选票归属仅本人可见，公共快照与事件只包含允许公开的数据。
- 保留请客规则与全员确认，不能由 host 代替付款人确认。
- 验收：两个独立浏览器能协作；他人不能编辑我的偏好或看我的选票；过时请求返回冲突而不覆盖。
- 在真实房间之上接入发布饭局、同城筛选、双向申请、容量事务、好友关系、退出/拉黑/举报。先做小范围试用，不发布虚构在线人数。

## 阶段 3：确认与交易交接

- 官方 create-order 支持返回 payH5Url；已核实 schema，未执行建单。先确认官方多用户授权方式，应用登录与麦当劳授权分开。
- 同城陌生人默认各自下单/各自支付，朋友可选一人代付；不能把应用分账当成官方一单多人支付。
- 最终重新核价、不可变快照、明确建单确认。
- 应用幂等、未知结果恢复、官方订单交接。
- 官方支付后只凭 query-order 状态更新，打开支付页或用户自述支付成功不直接改变订单状态。
- 验收：旧确认、旧报价、重复点击均不能重复或错误建单。
- 不要求为了测试下真实订单；可先验证到最终核价，交易执行待具体订单授权。
