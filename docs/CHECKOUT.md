# 下单与支付

更新：2026-10-22。当前只支持现在下单、普通到店自取、官方默认套餐搭配。代码已经接入 `create-order` / `query-order`，完整真实支付流程尚未完成实单验收；自动测试使用模拟接口。

## 页面操作

1. 选择餐品，或在共享餐桌勾选本次要结算的已选好成员，再汇总到真实餐单。至少 1 人即可，不要求人齐或所有人选好。
2. 官方核价，解决超预算提示后，点击“去下单确认”。这一步只查询、再次核价并保存确认草稿，不会创建订单。
3. 核对门店、餐品、套餐搭配与金额，选择官方返回的取餐方式，勾选确认，再亲自点击“确认下单”。这一步才创建真实订单，所选账户券可能被官方占用。
4. 创建成功后，点击“打开官方支付页面”。若没有可接受的官方 HTTPS 链接，使用麦当劳 App 的“我的订单”完成支付。付款由用户在官方页面完成。
5. 回到网页点击“我已支付 / 查询订单状态”，只按官方返回结果更新。打开链接、关闭弹窗或口头告知都不代表付款成功。

当前连接的麦当劳账号支付整单。页面上的各付各的、我请客是朋友间分账规则，不代表麦当劳支持一单分多个人付款。朋友参加共享选餐不需要提供 Token。

确认页列出本次成员，只有所选成员的已保存餐品计入该单。未参与本次的人继续选餐不会使该批次失效；所选成员改餐、移除或合拍取消/重开后，需重新汇总核价。共享结算中的餐品修改应回到共享餐桌完成。

## 数据与防重复

- 所有者订单记录：`data/checkouts.sqlite`；访客记录：`data/share/workspaces/<workspace>/checkouts.sqlite`。按当前授权的 SHA-256 指纹隔离，记录不含 Token 或明文券码；含订单号和支付链接，不要公开数据库。
- 服务端保存确认版本、商品配置摘要、金额、取餐方式和有效期（本地 3 分钟），提交前重新核价，价格、套餐、账号、所选成员版本或餐桌管理状态变化均拒绝继续；同时核对门店、所选成员与商品数量吻合。
- 创建调用前用 SQLite 事务持久化单次提交状态。重复点击、多个页面同时提交、进程重启都不会自动重发同一订单；已有未解决订单时，新的草稿会恢复原订单。
- 共享选择在创建调用前标记已提交，不能再次汇总，即使换账号也不能重复提交同一份已标记的选择。结果未知时保留标记；未参与结算的成员仍可继续选餐。已提交成员需要另点时新建餐桌。取消合拍或移除成员不会取消官方订单。
- 网络超时或响应格式无法确定时标为 unknown；进程中断保留 submitting。此时不能断言“没有下单”，也不能自动重试。先在麦当劳 App 核实；有订单号时可查询恢复。没有订单号的未知结果暂缺自动对账与解除阻塞界面，需要后续接入官方订单列表对账，切勿直接删库重试。
- 暂只接受 `mcd.cn` / `mcdonalds.com.cn` 及其子域名 HTTPS 支付链接，不推测或伪造支付地址。官方实际返回其他支付域名时先用 App 支付，待核实域名后再扩展。
- 支付金额、券扣减、支付渠道、回跳和真实状态变化未实单验证。测试与浏览器验收不执行真实“确认下单”。

## 团购券

当前 MCP 的账户券与美团、抖音券不是同一个资产体系。没有发现通用第三方券核销工具，也没有平台商家核销授权，因此页面不会接受券码并假装核销成功。按原购买平台的券面规则使用；仅在已按官方流程兑换至麦当劳账户、且当前门店返回可用后，才能在本页选择核价。

实现入口：`src/server/checkout.ts`、`src/providers/mcd-orders.ts`、`src/components/checkout-panel.tsx`。只读适配器的工具白名单继续禁止写工具；建单走独立边界。官方工具说明：[M-China/mcd-mcp-server](https://github.com/M-China/mcd-mcp-server)。
